# 15. Code Quality Expectations

### Preserve the Original Data

Do not overwrite `data/penguins.csv` or silently change its measurements.

### Use Readable Pandas Expressions

Prefer:

```python
heavy_penguins = penguins.loc[
    penguins["body_mass_g"] >= HEAVY_MASS_G
].copy()
```

rather than a complicated expression with unclear variables.

### Avoid Chained Assignment

Instead of modifying an ambiguous slice, make an explicit copy before adding columns.

### Keep Data Types Honest

Identifiers, categories, measurements, and years have different meanings. Do not turn missing numeric data into zero without a documented reason.

### Name Business Rules

Prefer `HEAVY_MASS_G = 4500` rather than scattering `4500` throughout your code.

### Give Functions One Responsibility

Keep inspection, transformations, and report preparation separate. Do not introduce classes unless you have a genuine need to hold state.

### Do Not Over-Engineer

The goal is **correct, readable data manipulation**, not a complex ML project or a general-purpose data framework.
